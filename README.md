# Personal Portal

一个本地运行、个人数据独立存储的个人工作/生活操作台。

代码公开，数据私有。日常就三件事：**记下要做的（Task）**、**记下刚发生的（Activity）**、**看一眼心力状态**。

---

## 快速开始

```bash
# 1. clone 代码
git clone <repository-url> personal-portal
cd personal-portal

# 2. 安装依赖
npm install

# 3. 配置个人数据目录
cp .env.example .env.local
#    编辑 .env.local，设置：
#    PERSONAL_DATA_DIR=/home/<you>/personal-portal-data

# 4.（换电脑时）把旧电脑的个人数据复制到该目录
#    personal-portal-data/portal.db、personal-portal-data/task-logs/ 等

# 5. 启动
npm run dev
# 打开 http://localhost:3000
```

> **代码与个人数据永久分离**：代码在 Git 仓库里，个人数据在 `PERSONAL_DATA_DIR` 里，两者互不相混。GitHub 上永远看不到你的个人数据。

## 三个页面，三个定位

| 页面 | 路由 | 定位 |
|------|------|------|
| 工作台 | `/workbench` | **现在**：创建/管理 Task，记录 Activity，点心力状态 |
| 日常 | `/daily` | **历史**：按日期查看过去所有 Activity 原始记录 |
| 回顾 | `/` | **看到什么**：日历热力 + 简洁统计（未来接 AI Review） |

侧边栏只保留「回顾」和「工作台」两个一级入口。「日常」从工作台的「查看全部 Activity」进入。

## 每天怎么用

打开网站进 **工作台**，只有三个动作：

1. **想到要做的事** → 建 Task（选分类 + 优先级）
2. **刚刚发生了什么** → 记一条 Activity
3. **此刻状态如何** → 点一下心力状态（自动留一条记录）

```
明确要做的事        → 创建 Task
过程中发现信息/想法/问题 → 记 Activity
事情做完了          → Task 标记「已完成」
心情/精力波动       → 点一下心力状态
```

---

## 工作台怎么用（Task）

- **创建**：选分类（工作/心智/身体/精神）+ 优先级（🔴高/🟡中/🟢低）+ 输入标题 → Enter 或「添加」。
- **当前任务**：待办 + 进行中混在一列，按你自己拖动的顺序排。
- **拖拽排序**：直接拖动卡片，把「现在最想做的」拖到顶部。优先级是重要程度，拖动顺序是执行顺序，两者独立。
- **改状态**：卡片上的状态下拉（待办 / 进行中 / 已完成），改「已完成」会移入归档。
- **改分类 / 优先级**：卡片上的 emoji 下拉。
- **备注**：点展开箭头，写备注，失焦自动保存；收起时显示「📝 预览」。
- **删除**：卡片右侧垃圾桶。
- **已完成归档**：默认收起显示最近 7 条，「已完成 (N)」可展开查看全部，也可「↩」恢复为待办。**只归档不清数据。**

---

## 工作台怎么用（Activity）

Activity 是低摩擦的「发生记录」，不是日记。可以记：做过什么、学到什么、遇到什么、一个想法、一个待处理问题、Debug 过程、生活琐事……任何不值得建 Task 又不想丢的东西。

- 输入是多行框，**Enter 换行，Ctrl/Cmd+Enter 提交**（或点「记录」）。
- 不要求分类、标签、优先级、情绪。

### 心力状态

点一下 `很低 / 较低 / 一般 / 良好 / 很高`，程序自动写一条 Activity「记录心力状态：X」。**能自动留的数据，不要求你重复记。**

---

## 日常（Daily）怎么用

Daily 是 Activity 的**历史库 / 原始记录库**：

- 默认查看全部，按天分组倒序。
- 按日期筛选。
- 每条带时间，悬停可删除错录。
- 是原始记录，**不会自动变成知识库**——先留下痕迹，整理是以后的事。

---

## 回顾（Dashboard）怎么用

回顾页是「从过去看到什么」：

- **日历热力**：一个月一屏，按天显示 Activity 数量强度；色点 = 心力状态，✓n = 当天完成任务数。
- **点某天**：看当天所有 Activity + 完成数 + 心力。
- **统计**：本周 Activity 数 / 本周完成任务数 / 今日心力。

---

## Daily 与 AI 的关系

### 当前版本

Daily 只做 **记录 → 保存 → 查看**。**当前没有 AI 总结，没有任何 AI 功能。**

### 未来（规划中，尚未实现）

```
Daily 原始记录 → 积累一段时间 → AI Review → 提炼出经验/知识/作品集/目标 → 长期资产
```

> Daily 是原始素材，不是最终知识库。记录时不需要整理。

## AI Review 触发方式

> **当前版本尚未实现 AI Review**，没有自动触发，也没有 AI 按钮。

未来计划优先做**手动周期 Review**（不是每天自动跑）：每周手动点一次「Review 本周」，AI 读最近 7 天的 Tasks / Task Logs / Activities，生成「本周完成 / 解决的问题 / 形成的知识 / 反复出现的问题 / 值得进知识库 / 值得进作品集 / 一直想做没行动 / 下周建议」。

> AI Review 的目标不是替你安排人生，而是**从真实发生过的事情里提炼信息**。

## 一次完整的日常示例

```
09:20  建 Task「调查 OBE HDMI 异常重启问题」（工作 / 高）
10:15  Activity「发现 UFS error code 5」
11:30  Activity「自测 20 次未复现」
14:10  Activity「想到可能和 Runtime PM 有关」
15:00  心力状态：一般
17:30  Task 标记「已完成」
18:00  Activity「最终确认是 UFS runtime PM 与 HDMI 冲突」
```

一眼看懂：**Task = 我要做什么，Activity = 我实际经历了什么。**

---

## Task + Activity 使用原则

- 「发现一个好用的命令」→ Activity 就够，不必建 Task。
- 「想到一个产品想法」→ Activity 就够。
- 「今天解决了一个 Bug」→ Activity 就够。
- 「**我要整理这个 Bug 的解决过程**」→ 这才建 Task。

> Task 用于需要行动的事；Activity 用于留下发生过的事。

## 数据与迁移

- **代码**：`git clone` / `git pull`
- **个人数据**：`PERSONAL_DATA_DIR` 指向的目录
- **换电脑**：clone 代码 + 恢复个人数据 + 配置路径

```
PERSONAL_DATA_DIR/
├── portal.db        # SQLite（Task / Activity / 笔记 / 习惯 / 心力 …）
├── task-logs/       # 任务日志月度导出（json / md）
└── future-data/     # 未来：attachments / exports / media …
```

真实路径写在本地 `.env.local`（已被 gitignore），仓库只提交 `.env.example`。

## 常见问题（FAQ）

**为什么 Activity 不需要分类？** 记录优先于整理，一分类摩擦就上来了。

**什么该建 Task？** 需要实际行动、以后要完成的事。

**什么该写 Activity？** 已经发生的事、发现、经验、想法、零碎信息。

**Activity 是不是日记？** 不是，更像 Activity Stream。

**必须每天写 Activity 吗？** 不是，想到就记。

**Activity 会自动整理成知识吗？** 当前不会，未来靠 AI Review（未实现）。

**心力状态会记到哪里？** 自动写一条 Activity，同时存进心力数据。

**数据在哪？** `PERSONAL_DATA_DIR`。

**换电脑怎么办？** 代码重新 clone，个人数据单独恢复，改 `.env.local` 路径。

**GitHub 上为什么看不到我的个人数据？** 这是设计目标——个人数据永不进 Git。

**那些职业/身体/心智/精神页面去哪了？** 已从导航移除（使用频率低），路由和数据都还在，只是不再作为一级入口。
